# Статья блога TT Max

Статьи живут только в `src/data/blog.ts` (UA + RU в коде; CMS к блогу не подключена намеренно).
Sitemap, `feed.xml`, `llms-full.txt`, список блога, hreflang и JSON-LD (BlogPosting, FAQPage, HowTo, Breadcrumb) строятся из данных автоматически — их не трогать.

**Что читать:** этот файл — всегда. `fields.md` — перед созданием статьи или нового блока. `visuals.md` — на шаге обложки и схем.
**Эталон** по плотности и тону — статья `alc-chy-zlc`: `grep -n '"alc-chy-zlc": {' src/data/blog.ts`, затем читать кусками (intro, одна секция, FAQ), а не всю.

## Новая статья — порядок
1. **Интент.** Тема и целевой запрос UA/RU — от пользователя. Если ключей нет, предложить 2–3 формулировки. Платные инструменты (Ahrefs) — только с разрешения и с ценой в юнитах. Коммерческий запрос («купить», «цена», «X Butterfly») — это категория или хаб, а не статья: сказать об этом и не писать.
2. **Пересечения.** Список статей: `grep -nE '^  "[a-z0-9-]+": \{' src/data/blog.ts`. Похожий интент — дополнить существующую статью, а не плодить вторую. Проверить хабы: `src/data/catalog/hubContent/`.
3. **Факты.** Только первоисточники: butterfly-global.com, правила ITTF и федераций, данные каталога (`bases.ts`, `products.ts`, `expert.ts` — через grep). Каждое число — с источником. Не выдумывать характеристики, цитаты, отзывы и личный опыт. Расхождение с каталогом — сообщить пользователю, молча не править.
4. **Текст.** Сразу обе локали. RU — естественный русский, не калька с UA. План показывать пользователю только при спорной теме, иначе писать сразу.
5. **Визуал.** Обложка обязательна; схемы — где есть данные (`visuals.md`).
6. **Перелинковка.** `relatedPosts` (3–4 статьи), плюс новый slug в `relatedPosts` 2–3 близких существующих статей. Внутренние ссылки — по правилам ниже.
7. **Проверка** (раздел ниже) → коммит → деплой по правилам CLAUDE.md. После деплоя проверить живую страницу и предложить пользователю «Запросить индексирование» в Search Console.

**Вставка в `blog.ts`:** новая запись — перед закрывающей `};` объекта `POSTS` (`grep -n '^};' src/data/blog.ts`), одним Edit. Над записью — комментарий: целевые запросы, откуда взяты числа, дата сверки (как у существующих статей).

## Обновление статьи
- Существенное изменение → новый `dateModified` (опечатки — без смены даты). `slug` не менять; если всё-таки нужно — 301 в `redirects()` в `next.config.ts`.
- Числа в тексте, таблицах и схемах меняются вместе: текст ↔ генератор схемы ↔ данные каталога.

## SEO/GEO-правила
- **Формат ≠ категория.** Статья = объяснение + таблица + 3–5 моделей ссылками, без цен и кнопок «Купить». H1 — вопросительный или информационный. Если за секунду не видно разницы со страницей каталога — это каннибал.
- **Title** ≤ 60 символов, в конце ` | TTMAX`. **Description** 110–158 символов, начинается с эмодзи по теме, содержит главный запрос и конкретику (числа). Длину проверять для обеих локалей — RU обычно длиннее.
- Главный запрос — в H1, title, первом абзаце intro и хотя бы одном h2. H1 и title дословно не совпадают.
- **slug:** транслит украинского запроса, коротко, `^[a-z0-9-]{1,80}$`.
- **Answer-first.** Первая секция — `id: "korotko"`: прямой ответ в 2–4 предложениях + таблица. Её цитируют ИИ-ассистенты.
- Первое предложение каждой секции отвечает на её h2. Каждый абзац содержит факт или вывод, без воды. Числа — с единицами, даты — абсолютные.
- **FAQ:** 6–9 реальных вопросов (как спрашивают в Google и на форумах). Ответ — 2–4 самодостаточных предложения, без «см. выше». Вопросы не повторяют h2 дословно.
- **HowTo:** `steps` — только в одной секции (разметка берётся из первой секции со `steps`). Шаги — действия.
- **Источники:** `officialSource` — главный первоисточник; `sources` — официальные первыми. Указывать только страницы, которые реально открывались и содержат факт.
- **Внутренние ссылки:** пути без локали (`/osnovaniya/alc`, `/butterfly/osnovaniya/viscaria`); `links` в секциях — на хабы и карточки; `relatedProducts` — 2–4; `rec` — не чаще одной на 2–3 секции.
- **Автор:** `author: "artem-maksymchuk"` (действующая практика). `opinion` заполнять только текстом, который дал владелец; иначе не заполнять. `rec.verdict` — фактический вывод из данных, не «личный опыт». От имени реальных людей не писать.
- Даты `datePublished` / `dateModified` — сегодняшняя дата, вручную (`YYYY-MM-DD`). Черновик — `draft: true`: не рендерится на проде и не попадает в sitemap.

## Проверка
1. `npm run typecheck`.
2. `npm run build 2>&1 | tail -15`, затем `npm run check:meta -- --build` и `npm run check:geo -- --build`.
3. Визуально: preview `ttmax-dev` → `/ua/blog/<slug>` и `/ru/blog/<slug>`. Обложка, таблицы на мобильной ширине, якоря оглавления. RU — худший случай по длине заголовка на обложке.
4. После деплоя: страница отдаёт 200, в HTML есть JSON-LD (`curl -s <url> | grep -c 'application/ld+json'`), есть OG-картинка.

## Экономия
- `blog.ts` весит ~600 КБ: никогда не читать целиком. grep → Read диапазона.
- Статью вставлять одним-двумя Edit, а не десятками мелких.
- Исследование: точечный WebFetch официальных страниц. Найденные числа сразу фиксировать в комментарии над статьёй, чтобы не искать их повторно.
